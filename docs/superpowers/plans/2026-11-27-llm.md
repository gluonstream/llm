# LLM Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the `graphify -start-llm`-style model controls with a friendly `llm` / `lmm` CLI that reports live model state and diagnoses load failures, while keeping the graph CLI working.

**Architecture:** A stdlib-only Python package in `~/projects/llm`, installed through symlinks in `~/.local/bin`. It reuses the existing llama.cpp profiles and health checks, adds a `doctor`/failure-explanation layer, and turns `graphify-model-service` plus the old flags into thin compatibility shims.

**Tech Stack:** Python 3 standard library (`unittest`, `argparse`, `subprocess`, `urllib`, `json`), POSIX shell shims, Homebrew llama.cpp.

**Spec:** `docs/superpowers/specs/2026-11-27-llm-design.md`

## Global Constraints

- Python 3.9-compatible stdlib only; no third-party imports; tests use `unittest` (pytest is unavailable in the graphify virtualenv).
- Service endpoint remains `http://127.0.0.1:18081/v1`; port `18081`.
- State lives in `~/.local/state/llm`; legacy state is `~/.local/state/graphify-model-service`.
- Model files stay at `~/.local/share/graphify-*`; do not move them.
- `graphify` and the graph-analysis CLI must keep working unchanged.
- Replace existing files only after saving `<name>.backup-YYYYMMDD-HHMMSS` beside them.
- Inkling 2 profiling requires llama.cpp >= 1.1.0; installed binary is `/opt/homebrew/bin/llama-server`.
- Log rotation threshold: 20 MB.
- Never kill or take over a listener on port 18081 that is not the managed llama-server.

## Review Focus

- Two models sharing a prefix (`glm-4.7-flash` vs a future `glm-…`) must raise an ambiguity error listing candidates, never silently pick one.
- A stale/reused PID in `process.json` must be reported as stopped, even if that PID now belongs to another program.
- A foreign listener on 18081 must produce a clear error and must not be stopped or reused.
- A missing or zero-byte GGUF must be reported by `list`/`doctor` and fail `start` fast rather than after the readiness timeout.
- Reading the 130 MB `server.log` must seek from the end and never load the whole file into memory.

import json
import os
import tempfile
import unittest
from pathlib import Path
from unittest import mock

from llm import service

class LogTest(unittest.TestCase):
    def test_tail_reads_only_the_end(self):
        with tempfile.TemporaryDirectory() as tmp:
            path = Path(tmp) / "server.log"
            path.write_text("old\n" + "x" * 1000 + "\nlast line\n")
            self.assertTrue(service.tail_text(path, max_bytes=64).endswith("last line"))

    def test_rotate_at_threshold(self):
        with tempfile.TemporaryDirectory() as tmp:
            path = Path(tmp) / "server.log"
            path.write_text("a" * 200)
            self.assertTrue(service.rotate_log(path, max_bytes=100))
            self.assertFalse(path.exists())
            self.assertEqual((Path(tmp) / "server.log.1").stat().st_size, 200)
            self.assertFalse(service.rotate_log(Path(tmp) / "server.log.1", max_bytes=100))

    def test_last_failure_uses_tail(self):
        with tempfile.TemporaryDirectory() as tmp:
            path = Path(tmp) / "server.log"
            path.write_text("E llama_model_load: error loading model: "

                                "repeat_penalty": 1.0}}

        self.assertIn("/tmp/x.gguf", args)
        self.assertIn("4096", args)
        self.assertIn("x-alias", args)
        self.assertIn("--port", args)

class SafetyTest(unittest.TestCase):
    def test_stale_pid_is_not_running(self):

            pidfile.write_text(json.dumps({"pid": os.getpid(), "identity": "old-identity"}))
